# 로그 해석 기준

`log_reference.json`은 제공된 `시스템로그 및 알람로그 정리본.xlsx`의 세 시트를 UTF-8 JSON으로 옮긴 기준 파일입니다. 원본 설명, 예시, 해결방법, 코드 근거를 보존합니다. 별도 DB나 임베딩 없이 Python의 `json`으로 읽을 수 있습니다.

## 구성

| log_type | 원본 시트 | 항목 수 |
| --- | --- | ---: |
| system | 시스템로그 | 235 |
| system_developer | 시스템로그 개발자용 | 18 |
| alarm | 알람로그 | 27 |

`entries`의 각 항목은 다음 정보를 갖습니다.

- `id`: 로그 종류와 원본 INDEX를 결합한 식별자
- `category`, `code`: 기능 분류와 코드. 코드는 문자열로 보존하며 심각도로 해석하지 않습니다.
- `message_template`, `tags`: 원본 로그 문구와 선두 대괄호 태그
- `description`: 원본 로그 설명
- `example`, `recommended_action`: 원본 예시와 해결방법. 없는 값은 `null`입니다.
- `source_note`: 원본 변경 내역과 코드 근거
- `reference_only`: 원본의 ‘기존 미출력 / 중복’ 분류 여부. 18개 항목입니다.
- `source`: 원본 시트명과 Excel 행 번호

## 다음 연결 단계

1. 시스템로그는 `system`과 `system_developer`에서 함께 후보를 찾습니다. 알람로그는 `alarm`에서 찾습니다.
2. 코드가 일치하는 후보 안에서 실제 메시지와 템플릿·예시를 비교합니다. 같은 코드의 항목이 여러 개이므로 첫 후보를 정답으로 선택하지 않습니다.
3. 기본 검색에서는 `reference_only`를 제외하고, 과거 로그 확인이 필요할 때 참고합니다.
4. 선택한 기준의 설명과 원본 로그를 LangChain에 전달하고, 답변에 기준 `id`와 원본 로그 줄 번호를 남깁니다.

문구에는 `%s`, `%d`, `%.1f` 같은 자리표시자와 `START/END` 같은 설명 표기가 섞여 있습니다. 그대로 정규식으로 실행하면 안 됩니다. 예시에 현재 템플릿과 다른 과거 문구가 있으므로 버전 차이도 고려해야 합니다.

원본에 없는 장애 원인, 임계값, 해결방법은 추가하지 않았습니다. 원본 셀에 있는 문장은 참고 데이터이며 모델에 대한 실행 지시로 취급하지 않습니다. 이번 단계에서는 기준 파일만 생성했으며 검색과 LangChain 연결은 아직 구현하지 않았습니다.
